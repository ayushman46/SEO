## ADR-018 — Scoring weights for the T016/T020 checks (audit-engine; Fable's request)
New check weights inside their category (the existing weights are unchanged): GEO: `geo.raw-html-facts` 8, `geo.ai-crawler-probe` 8, `geo.snippet-eligibility` 8, `geo.fact-consistency` 6, `geo.content-format` 5, `geo.review-signals` 3 (plus `geo.ai-clarity` 11 from ADR-015). SEO: `seo.soft-404` 4, `seo.bing-indexnow` 3. GEO's available weight went from 88 to 126 (137 with an LLM key), so each older GEO check now counts for a smaller share. **Messaging consequence:** a site that passes the new checks gains GEO points without changing anything (python.org GEO 74 → 81, overall 75 → 79); a site that fails one loses a little (vercel.com GEO 97 → 94, overall 96 → 95, for crossed-out prices and an address that is only in JSON-LD). Low-confidence checks are held down on purpose: `geo.review-signals` (correlational, vendor-run evidence) and `seo.bing-indexnow` (invisible verification methods, private IndexNow keys) have the smallest weights, and `seo.bing-indexnow` never returns `fail`. Network-backed checks (`geo.ai-crawler-probe`, `seo.soft-404`) are `unavailable` when skipped, so they're left out of the score rather than counted against the site.

## ADR-017 — Live AI-crawler probe with a labelled simulated User-Agent (Fable's ruling, T016 C)
`geo.ai-crawler-probe` requests the audited site as six AI crawlers (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, PerplexityBot, bingbot; Google-Extended is a robots.txt-only token, so it isn't probed). **User-Agent:** the bot's product token plus our own marker in the same string, e.g. `Mozilla/5.0 (compatible; GPTBot/1.3; simulated-by seenhqbot/1.0; +https://seenhq.vercel.app/bot)`. The UA is built only by `simulatedUserAgent()` from a fixed token allowlist, so the marker can't be left out. We never send a bot's official UA verbatim, never claim to be the vendor in any other header, and never send IP-verification or forwarding headers. There is no "browser" request: the baseline is the response our crawler already got as seenhqbot. If seenhqbot itself was refused, the probe is reported as inconclusive. **Scope and limits:** audited host only (homepage + up to 2 crawled pages, robots.txt, llms.txt when present), through `safeFetch` (SSRF-pinned, no redirects followed). URLs that robots.txt disallows for seenhqbot or for the simulated bot are not probed. HEAD first; GET (64 KB cap) only when HEAD is refused (4xx/5xx other than 429) or unsupported, at most 2 GETs per bot. Pages use the same HTML Accept header as the crawler (vercel.com serves Markdown to `text/plain`). Concurrency 2, 2.5 s per request, 6 s for the whole probe, run alongside the AI phase, skipped below 3 s of usable budget. **R3 revision (M3, M4):** a 429 counts as "not tested (rate limited)", never as refused, and stops any further probe requests. Results are cached per host for 15 minutes in memory, per server instance (not shared across instances; no DB cache yet). When only bots whose operators publish IP ranges (bingbot, GPTBot, OAI-SearchBot, ChatGPT-User, PerplexityBot) are refused by an unnamed layer while other bots get through, the finding is low severity and worded "may be verifying crawler IP addresses; we cannot tell from outside". **Request budget per audit against the audited host (worst case):** crawl ≤ 45 (homepage 4, robots/sitemap/llms 12, http→https 1, 2 declared sitemaps 8, 5 pages 20) + probe ≤ 42 (5 targets × 6 bots = 30 HEAD + ≤ 12 GET; 0 when cached) + soft-404 1 = **≤ 88** (was ≈ 106). A typical clean site: ≈ 10 crawl + 24-30 HEAD + 1 ≈ 35-41. **Layer naming** uses response headers and block-page text. Checked with curl on 2026-11-23: Cloudflare (`server: cloudflare`, `cf-ray`, challenge page with `/cdn-cgi/challenge-platform/`), Akamai (`akamai-grn` header and an entity-encoded "Access Denied … Reference #" page), Vercel (`server: Vercel`, `x-vercel-id`), Sucuri (`server: Sucuri/Cloudproxy`, `x-sucuri-id`), Imperva (`x-iinfo`, `x-cdn: Imperva`), CloudFront (`x-amz-cf-id`, `via … cloudfront`). Assumed from vendor docs, not seen live: `cf-mitigated: challenge`, `x-vercel-mitigated`, `x-sucuri-block`, the Wordfence block-page text, DataDome, Netlify, Fastly. Anything unknown is reported as "your host or firewall". Every user-facing string says: "Simulated from our servers with a labelled test user agent; sites that verify crawler IP addresses may treat the real bot differently."

## ADR-016 — Instant quote rules and order intake (architect-backend, T019)
**What:** `src/lib/quote/` (pure, client-safe) turns audit issues into a quote; the contact form can carry it as hidden fields (`quote_currency`, `quote_total`, `quote_fixed`, `quote_items`, `audit_id`, `audit_url`). No payment processor: an order is a contact submission plus an invoice.
**Rules:**
- **Prices come only from `src/lib/quote/catalog.ts`.** One table, USD and INR, mirroring `src/content/services.ts` / `pricing.ts`; `tests/quote/catalog.test.ts` fails if an amount or its "From" wording drifts. A missing rupee price (Content & entity today) is shown as "Price confirmed by email", never guessed.
- **"From" prices are never shown as fixed.** Any "from" or on-request line, more than 6 pages, more than 20 priced issues, or any `involved`-effort fix makes `fixedTotal` false, and the UI must say a person confirms the price within 1 business day. The Fix sprint is "From $199" on the public pages, so a quote containing it is never fixed until the founder publishes a fixed base scope.
- **The DIY list is always shown.** Items an owner can do in minutes (titles, descriptions, H1s, noindex checkbox, alt text, footer contact text) are listed as DIY and are not priced unless the owner picks them. Low-severity items and deliberate choices (blocking AI training bots) are listed as safe to ignore.
- **No invented urgency, discounts or add-ons.** No expiry, no countdown, no "save" wording. The only bundle is scope-based: the sprint already sets up robots.txt, so robots.txt-level AI crawler blocks are folded into it instead of adding the $149 unblock (server/CDN blocks from the probe still need the unblock). Monitoring is never added to a quote; the Full audit appears only as an unpriced alternative.
- **Tax-exclusive, said up front.** Every quote carries `taxNote` ("Prices exclude applicable taxes") to avoid drip pricing until tax-inclusive totals are decided.
- **Server never trusts client prices.** The contact action re-checks every item's slug, price and from-flag against the catalog, recomputes the total, stores both (`quote` jsonb with `valid`, `quote_valid` column) and can only downgrade "fixed", never upgrade it. A malformed attachment is dropped and flagged, never blocks the message. Migration `0002_quote.sql` adds nullable columns; `audit_id` is deliberately not a foreign key (audits may run without a database).

## ADR-015 — AI insights via the NVIDIA API catalog (audit-engine, T014)
**Provider:** `POST https://integrate.api.nvidia.com/v1/chat/completions` (OpenAI-compatible), `Authorization: Bearer $NVIDIA_API_KEY`, plain `fetch`, no SDK, server-side only (no CSP change). Without `NVIDIA_API_KEY` the phase is skipped, `geo.ai-clarity` is `unavailable` and every score equals the pre-T014 result.
**Models (env-overridable `NVIDIA_MODEL`, `NVIDIA_MODEL_FALLBACK`):** primary `nvidia/nemotron-3.5-lightning-30b-a3b` (30B MoE, 3B active, so fast; up to 1M context), fallback `google/gemma-4-31b-it` (31B dense, 256K context, a different model family and rate pool). **Evidence, fetched 2026-11-23 with curl:** both ids are listed by `GET /v1/models` (33 models); context lengths from the docs.api.nvidia.com model pages; both request schemas document `chat_template_kwargs: {"enable_thinking": bool}` defaulting to true, so we send `false` for these two ids only (any other env-supplied id gets a plain body). Rate limits from build.nvidia.com/faq: "up to 40 rpm", "10,000 requests per day", "may vary by model". **Not verified / not used:** `response_format` / JSON mode and `nvext.guided_json` are not documented on these models' reference pages, so we ask for JSON in the prompt and parse defensively. No live call was made (no key on the dev machine). The docs' static model table is stale vs `/v1/models`; `/v1/models` wins.
**Limits:** 2 calls per audit, in parallel (analysis is required, drafts optional), each with at most one retry on 429/5xx/network error using the fallback model, so at most 4 requests per audit. The phase starts after crawl + deterministic checks, gets `min(20 s, remaining − 2 s)`, is skipped below 6 s remaining, honours the caller's AbortSignal, and never throws. Input ≤ 22k chars (homepage text 7k, other pages 2.5k, max 6 pages); `max_tokens` 1,600 / 1,800; response body capped at 256 KB; temperature 0.2.
**Injection hardening:** page text sits in `<<<BEGIN_PAGE_DATA>>>` blocks, our delimiter tokens (and `<<<`/`>>>` runs, control and bidi characters) are stripped from it, the system prompt says block content is data and never instructions. Every output field is Zod-validated and length-capped; any HTML tag, `javascript:`/`data:` scheme, off-host URL (allowed only: the audited host, schema.org in JSON-LD, and profile links the site itself links to via `<a href>`), or email/phone not present in the input drops the field (readback → whole analysis dropped). `sourceUrl` must be one of the crawled pages. JSON-LD is `JSON.parse`d and re-serialised by us. `clarityScore` is computed by us (facts 60% / questions 40%, weighted facts). Output is rendered as plain text only.
**Fallback:** any failure → `ai: null`, check `unavailable`, a plain note; drafts failing alone → insights with all drafts null. Honesty rule: copy says "how an AI model reads your site", never what ChatGPT/Gemini say. Privacy: text from the audited public pages is sent to NVIDIA's hosted API (privacy policy update is content-seo's T014 part).

## ADR-014 — Database TLS: the URL decides, default is verified (architect-backend, R2 #10/#21)
The app and `scripts/migrate.ts` no longer force `ssl: "require"` (postgres.js maps that to "no certificate check" and lets it override the URL's `sslmode`). Shared helper `src/lib/db/ssl.ts`: if the URL has `sslmode`, `ssl` or `sslrootcert` (or `PGSSLMODE` is set), the URL wins (`verify-full`, `sslrootcert=system|<path>`, `disable` for docker-compose). Without TLS parameters: localhost gets TLS off, any other host gets `verify-full`. Trade-off: a host with a private CA (Supabase) and no `sslrootcert` now fails to connect instead of silently connecting unverified; the operator adds the CA path or opts out explicitly with `sslmode=require`. DB timeouts are 5 s (connect and query) so best-effort DB calls fit inside the routes' `maxDuration`; `/api/audit` measures its 50 s crawl budget from request start. Migrations use `DATABASE_URL_UNPOOLED` when set and take a transaction-scoped advisory lock (`pg_advisory_xact_lock`, 60 s `lock_timeout`) per step, which is safe on transaction-mode poolers.

## ADR-013 — Rate limiting at launch without a database (founder decision: launch without DATABASE_URL)
The site launches on Vercel serverless with no `DATABASE_URL`, so the in-memory limiter (ADR-006) is the production limiter for now. What it does and does not do:
- **Per instance, best effort.** Counters live in one function instance's memory. Vercel spreads traffic over several instances and cold starts begin empty, so one client can get up to `limit x warm instances` per hour (5/h audits, 10/h unlocks, 5/h contact). It is not a per-IP guarantee and nothing in code can make it one without shared state.
- **Client identity:** salted hash of the IPv4 address or the IPv6 **/64** prefix (stops trivial rotation inside one IPv6 allocation). Requests with no usable client IP all share one bucket per scope with half the normal limit. On Vercel `x-forwarded-for` is always set, so that bucket only fills if the deployment is misconfigured.
- **Per-instance in-flight cap for `/api/audit`** (`src/lib/security/concurrency.ts`): at most 4 concurrent audits per instance and 1 per client per instance; extra requests get 503 `server_busy` with `Retry-After` and do not consume quota. This bounds the CPU, memory and outbound fetches one instance can be made to do; it does not bound totals across instances.
- **Logging:** in production the first memory-answered request per instance logs a warning naming `DATABASE_URL`.
Residual risk: a determined client (or a botnet with many IPs) can still run more audits than intended, which spends crawl time and the `PAGESPEED_API_KEY` quota and can spam the contact notification. Mitigations, in order: set `DATABASE_URL` (every limiter switches to the shared Postgres fixed window with no code change); add a Vercel Firewall rate-limit rule (POST `/api/audit` 5/h, `/api/audit/unlock` 10/h, contact Server Action POSTs 5/h, keyed on IP); a KV store would need a new dependency and a separate decision. Tracked as a launch known issue.

## ADR-012 — Static CSP with 'unsafe-inline' scripts in v1 (architect-backend)
CSP is a static header from `next.config.ts` `headers()`, not per-request nonces. Nonces force every page to render dynamically, which defeats Cache Components' static shells for the marketing pages. Cost: `script-src 'self' 'unsafe-inline'` (+ `'unsafe-eval'` in dev only) weakens XSS protection, so we rely on React's escaping and never render untrusted HTML. Allowed origins: `https://va.vercel-scripts.com` (Vercel Analytics), `https://vitals.vercel-insights.com` (connect). `img-src 'self' data: blob:` means no third-party images (e.g. audited sites' favicons) unless added here. `frame-ancestors 'none'` + `X-Frame-Options: DENY`. HSTS and `upgrade-insecure-requests` in production only. Revisit with nonces / SRI if we add user-generated content. On Vercel **preview** deployments only (`VERCEL_ENV=preview`), the Vercel Toolbar origins are added (`https://vercel.live` in script/style/img/font/connect, `frame-src https://vercel.live`, `wss://ws-us3.pusher.com`, `https://vercel.com`, `https://assets.vercel.com`); the production policy is unchanged (R2 #19).
Related Next 16 constraint: with `cacheComponents: true` the `dynamic` and `runtime` route segment exports are not allowed, so `/api/audit` sets only `maxDuration = 60` and `/admin` reads `headers()` inside `<Suspense>` instead of `dynamic = "force-dynamic"`.

## ADR-010 — Plain Postgres via `DATABASE_URL`, provider-agnostic
Supabase free tier is at its 2-active-project limit on the founder's account, and without auth Supabase's main advantage is gone. We talk to any Postgres through `postgres` (porsager, tiny, no ORM) with SQL migrations in `/db/migrations`. Recommended host: Neon free tier (never deleted; auto-suspends and resumes in <1s). Supabase still works (paste its pooled connection string). Every table has RLS enabled with no policies, so if it ever lives on Supabase the anon/public API cannot read it — only the server connection can.
If `DATABASE_URL` is missing, the app still runs: audits work, and lead/contact submissions are logged server-side and the user sees success (dev/demo only; STATUS.md flags it).

## ADR-009 — Stateless email gate with sealed results
The free audit returns a partial report plus the **full result sealed with AES-256-GCM** (`AUDIT_SEAL_SECRET`). To unlock, the client posts the sealed blob + email; the server decrypts, stores the lead, and returns the full report. No DB round-trip needed to hold results, works on serverless, and the client cannot read the full report without the email step. Seals expire after 2 hours.

## ADR-008 — Synchronous audit, 60 s hard budget
No job queue in v1. `POST /api/audit` runs homepage + up to 5 internal pages with a global 55 s budget (`maxDuration = 60` on Vercel). Per-request timeout 8 s, max 2 MB per HTML page, max 3 redirects, each hop re-validated against SSRF rules.

## ADR-007 — SSRF protection
Only http/https on ports 80/443. Hostname resolved via DNS; every resolved address checked against private/reserved ranges (IPv4 + IPv6 incl. mapped addresses, loopback, link-local, CGNAT, metadata 169.254.169.254). The socket connects to the **validated IP** (custom `lookup`) to defeat DNS rebinding. Redirects followed manually and re-validated.

## ADR-006 — Rate limiting
Postgres fixed-window counter table when `DATABASE_URL` exists, in-memory fallback otherwise (per instance, best effort; see ADR-013). Audit: 5 per IP per hour. Unlock: 10 per IP per hour. Contact: 5 per IP per hour. IPs are stored only as salted SHA-256 hashes.
